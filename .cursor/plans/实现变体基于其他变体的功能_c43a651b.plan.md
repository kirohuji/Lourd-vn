# 实现变体基于其他变体的功能

## 需求分析

1. **继承关系**：变体 A 可以基于变体 B，合并时先合并基础变体 B 的标签，再合并 A 的标签
2. **循环依赖检测**：防止变体 A 基于变体 B，变体 B 基于变体 A 的循环情况
3. **继承范围限制**：只能基于同一 Base Prompt 或 Character Prompt 下的变体
4. **UI 设计**：在创建/编辑变体时添加下拉选择框选择基础变体
5. **默认行为**：如果没有选择基础变体，使用 Base Prompt 或 Character Prompt 的 `basicPrompt` 作为起点（保持现有行为）

## 实现细节

### 循环依赖检测算法

```typescript
async checkCircularDependency(
  variantId: number,
  parentVariantId: number,
  basePromptId?: number,
  characterPromptId?: number,
): Promise<void> {
  const visited = new Set<number>();
  let currentId = parentVariantId;
  
  while (currentId) {
    if (currentId === variantId) {
      throw new BadRequestException('检测到循环依赖');
    }
    if (visited.has(currentId)) {
      break; // 已经检查过，避免无限循环
    }
    visited.add(currentId);
    
    const variant = await this.prisma.promptVariant.findUnique({
      where: { id: currentId },
      select: { parentVariantId: true },
    });
    
    if (!variant) break;
    currentId = variant.parentVariantId || undefined;
  }
}
```

## 测试要点

1. **创建基于其他变体的变体**：选择基础变体后，合并结果应该先包含基础变体的标签
2. **循环依赖检测**：尝试创建循环依赖应该被拒绝
3. **跨 Prompt 继承限制**：尝试选择不同 Prompt 下的变体应该被拒绝
4. **默认行为**：不选择基础变体时，行为应该与之前一致
5. **编辑基础变体**：可以修改变体的基础变体
6. **删除基础变体**：如果基础变体被删除，子变体应该如何处理（需要决定：设为 null 或阻止删除）

## 注意事项

- 需要处理基础变体被删除的情况（建议：阻止删除有子变体的变体，或提供迁移选项）
- 更新变体的基础变体时，需要重新计算 `mergedPrompt`
- 前端需要实时预览基于基础变体的合并结果
